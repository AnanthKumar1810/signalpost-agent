# Signalpost project status

The current code passes 63 automated tests, including a mocked 1,000-company batch. A live 100-company run returned 100 terminal profiles in 95,067 ms, using 314 requests. All 100 BRREG identities and role lists were available; finance data was available for 99 companies, with one source HTTP 500. A fresh retry of that same company produced another HTTP 500, so the agent leaves the finance claim failed. Website and vacancy coverage remain sparse. The run made no paid provider calls. Exact counts and limitations are recorded in [QA_TEST_REPORT.md](QA_TEST_REPORT.md), and its local judge assessment is in [SIGNALPOST_JUDGE_REPORT.md](SIGNALPOST_JUDGE_REPORT.md).

The finance adapter now follows BRREG's documented organization-number path and retries one transient source failure. Website fetching uses a hostname-pinned HTTPS connection and keeps TLS hostname verification enabled. Website activity extraction checks dated same-company news links; optional LLM web-search citations remain candidates until the cited page's quote, identity and date are fetched and matched. A final provenance gate drops facts whose source snapshot, evidence field, family or organisation number does not align. The five reference projects have pinned revisions and isolated checks in [REFERENCE_EVALUATION.md](REFERENCE_EVALUATION.md); Dataforge and python-brreg suites passed, Company Research Agent's offline curation path was behaviorally checked, and Crawl4AI's dependency, test-runner and fallback-expectation issues are explained there.

Builderr's current page requires a 100-company smoke test/report; it does not require 1,000 precomputed company profiles. The local 1,000-company test is fixture-backed. This GitHub push publishes code and test evidence; it does not submit the project to Builderr or establish a Builderr score or qualification. The official evaluator controls the score against its checked collection.
