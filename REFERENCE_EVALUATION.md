# Reference implementation review and isolated checks

Reviewed 18 October 2026 from shallow Git clones pinned to the commits below. These are separate projects and were not added as runtime dependencies to Signalpost.

| Reference | Inspected revision | Architecture and useful idea | Isolated check and result | Decision for Signalpost |
|---|---|---|---|---|
| [Fire Enrich](https://github.com/mendableai/fire-enrich) | `94e061dc5bab94e5838cceb8b3d5e6af329d2d50` | Next.js enrichment app that combines Firecrawl extraction with OpenAI synthesis. Its setup requires Firecrawl and OpenAI credentials. It enriches email/domain leads, so brand/domain identity is not enough for this challenge's legal-entity key. | `npm test -- --runInBand` → not runnable: package has no `test` script. `package.json` exposes dev/build/start/lint only; dependencies were not installed, no API keys were used. | Reuse source-specialized extraction and attribution ideas. Do not introduce per-company paid crawling/LLM orchestration as the default batch path. |
| [Company Research Agent](https://github.com/guy-hartstein/company-research-agent) | `80ed5040195fd8aad7225dfc3c2a80ecbaa336c5` | LangGraph workflow with research analyzers, collection, curation, briefing and editing. The collector uses Tavily and the report nodes use a configured LLM. | `python -m compileall -q .` passed. The repo has no test files. An isolated offline behavior check of its real `Curator.evaluate_documents` passed: it retained a 0.82-score result and a first-party company page, and rejected a 0.39 result and malformed score. No API keys were used; the network-backed graph was not run. | Its planner/curator separation is useful for a later opt-in deep-research mode. It is too costly and heavy for each company in the bounded official batch. |
| [Dataforge / FORGE](https://github.com/Nuclear-Marmalade/dataforge) | `e9059821f090f217cb708317869bcc06611fb45b` | Python enrichment CLI with web extraction, optional AI, database adapters and checkpoint/recovery code. It includes a pytest suite and optional development dependencies. | `python -m compileall -q forge` passed. Isolated `python -m pytest forge/tests/test_smoke.py -q` passed **5/5** in 0.13 s after placing pytest and temporary files inside the workspace. | Adopt bounded deterministic extraction, state snapshots and safe recovery patterns. Keep its database/optional-AI stack out of the minimal Signalpost runtime. |
| [python-brreg](https://github.com/crdbrd/python-brreg) | `013575b8d83c22bbf14fd8acb67ae2cd30b554f5` | Typed Python client for BRREG open APIs, backed by Pydantic and an HTTP client. This is the closest source-specific reference. | Installed pytest and dependencies into an isolated workspace target. `python -m pytest tests -q` passed **43/43** in 0.41 s. A direct isolated smoke of its `OrganisasjonsnummerValidator` also normalized both `923 609 016` and integer `923609016` to `923609016`. | The existing Signalpost adapter keeps the standard-library-only deployment. Retain org-number-first retrieval and the tested normalization/checksum gate; use the official schema as authority. |
| [Crawl4AI](https://github.com/unclecode/crawl4ai) | `94b67888ca8b335ff2121423a50e06dd27661922` | Async browser-based crawler with extraction strategies, caching, markdown and LLM integrations. The selected test imports the package root, which eagerly loads much of this runtime. | The first test collection failed because the isolated environment lacked `pyOpenSSL`; after adding dependencies, collection also required `aiosqlite`, `aiofiles`, `lxml` and `lark`, a writable `CRAWL4_AI_BASE_DIRECTORY`, and pytest's async plugin. With dependencies available, direct checks of the actual dispatcher passed for a matching PDF rule, the default rule, and an empty rule list. The checked-in async pytest case is not marked for asyncio and its expected fallback does not match the default-config behavior, so the repository test did not provide a reliable passing result. No browser install or live crawl was attempted. | Use only the small amount of same-domain, robots-checked retrieval needed here. Browser rendering is deferred unless the checked sample shows useful facts are inaccessible in static HTML. |

The commands actually run were:

```text
python -m compileall -q .                    # Company Research Agent — passed
python -m compileall -q forge                # Dataforge — passed
python -m compileall -q crawl4ai             # Crawl4AI — passed
python -m pytest forge/tests/test_smoke.py -q # Dataforge — 5 passed
python -m pytest tests -q                  # python-brreg — 43 passed
python -m pytest tests/test_config_selection.py -q # Crawl4AI — setup required OpenSSL/other deps, writable data dir and async plugin; selected test has an expectation mismatch
npm test -- --runInBand                      # blocked: no test script
```

These checks compare repository architecture and selected behavior; they are not a head-to-head accuracy or performance benchmark. Dataforge's smoke suite and python-brreg's complete 43-test suite passed. Company Research Agent's offline curation behavior passed without provider keys. Fire Enrich has no test script. Crawl4AI's dependency/setup blockers and the checked-in test's async/fallback mismatch are documented above; its actual dispatcher selection was smoke-checked directly. No API credentials or browser installation were configured. A matched-data accuracy/runtime/cost benchmark across all five frameworks remains unmeasured. The current Signalpost suite passes 63/63 tests and its 100-company live batch is recorded in `QA_TEST_REPORT.md`.
